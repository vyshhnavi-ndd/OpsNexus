OpsNexus local run guide

Production-style single application

1. From D:\OpsNexus, start the existing Exasol Personal deployment if needed:
   .\Deployment\exasol.exe start
2. Build the dashboard after frontend changes:
   cd frontend
   npm install
   npm run build
   cd ..
3. Start the integrated Flask app from the repository root:
   & '.\synthetic-data\.venv\Scripts\python.exe' -m flask --app api.app run --host 127.0.0.1 --port 5000
4. Open http://127.0.0.1:5000/

The integrated app uses api/.env and requires a dedicated, read-only OPSNEXUS_API identity with validated TLS. It serves the findings dashboard and the curated Llama assistant from one origin. Set OLLAMA_URL (loopback only) and OLLAMA_MODEL in api/.env for the assistant. The assistant retrieves only OPS_INTEL.V_FINDINGS; it does not generate SQL.

Logesh dashboard with the intelligence engine

The Logesh dashboard keeps its staging and ADF panels on the backend at port 5000 and reads intelligence findings from the safe OPSNEXUS_API service at port 5001. Start Exasol if needed, then start the findings service from D:\OpsNexus:
   & '.\synthetic-data\.venv\Scripts\python.exe' -m flask --app api.app run --host 127.0.0.1 --port 5001

The existing backend at port 5000 must use an authorized non-SYS account with validated TLS before it is restarted. Its local credentials are not copied into api/.env. From exasol-dashboard/, start Vite with npm run dev and open http://127.0.0.1:5173/. Select Intelligence Findings to see records from OPS_INTEL.V_FINDINGS; the database explorer remains on OPS_STAGE.

Frontend development

From frontend/, run npm run dev. Vite proxies API requests to Flask on 127.0.0.1:5000. Do not use the supplied legacy backend as a substitute: it now refuses SYS, certificate-validation bypass, unapproved schemas, and arbitrary SQL. Its local backend/.env still needs an authorized non-SYS identity and validated TLS before its legacy ADF and database explorer routes can run.

Azure configuration note

The supplied legacy backend uses a service principal configured through local environment variables. That is not automatic sign-in with the interactive Azure user. Keep the secret out of source control and use least-privilege Azure roles. ADF pipeline artifacts and Power BI assets still need to be supplied/verified by their owner.
